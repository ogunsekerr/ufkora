# Node.js / PHP security baseline — 2026-10-26
Scope: repository source and Vercel project settings for UFKORA and Dersakış.
Official advisories:
- https://nodejs.org/en/blog/vulnerability/october-2026-security-releases
- https://thephp.foundation/blog/2026/10/21/todays-php-security-release-and-how-were-strengthening-php-security/
- https://vercel.com/docs/functions/runtimes/node-js/node-js-versions

The PHP emergency fixes are 8.2.35, 8.3.36, 8.4.27 and 8.5.12. No PHP application or PHP runtime was identified in either project.
Node security releases: 22.23.4, 24.22.1 and 26.12.1. Both Vercel projects select Node 24.x; exact patch was not present in the old build logs. A major-version setting alone does not prove patch installation.
This change enforces Node >=24.22.1 <25 at server startup, logs only the runtime version, and permits subsequent patched Node 24 releases. Old versions fail closed. Dersakış also checks before build and narrows its previous >=20.9.0 engine range.
Vercel controls minor/patch selection. This guard does not patch the platform; it prevents this application from starting below the audited baseline.
Tests cover rejected unpatched versions, prerelease versions, unsupported major versions and accepted patched versions. No exploit requests, user-data operations or emails are required.
This targeted review does not establish absence of unrelated application vulnerabilities or compromise.

- UFKORA preview: dpl_45CdMk872v32XXGFRYERviddJeyf — GET /api/contact failed the runtime baseline check.
- Dersakış preview: dpl_DC58YzR4NBzF9F2nD7rkAZRyWckd — GET /giris failed the runtime baseline check.
The production branches have NOT been merged or redeployed by this security task. Preview build success is NOT runtime patch proof.
The strict guard intentionally stops an unpatched runtime. Do not release these changes until the provider supplies a patched runtime and both endpoints pass.
Provider bulletin: https://vercel.com/kb/bulletin/node-js-security-advisory (24 Oct 2026): managed runtime rollout is in progress; WAF protects known inbound patterns but not fetched responses.
Vercel customers can select a major runtime, not directly install a minor/patch release. Rebuilding alone did not resolve this observed mismatch.
